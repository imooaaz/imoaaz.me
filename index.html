Where I've worked

What each role involved, in plain engineering terms. In short: I make sure software is built, shipped, and tested so attackers can't break it.

  1. Present

    Co-Founder & Product Engineer

    Raqyan Co-founder

    I co-founded Raqyan and run how our software goes from code to production, with security built in from the start instead of added at the end.

    • Product delivery: own the release process that takes features from development to users.
    • Product security: make sure what we ship is safe to put in front of customers.
    • DevOps & DevSecOps: build and maintain the automated build, test, and deploy pipeline (CI/CD), including the automated security checks that run on every release.

  2. Feb 2025 — Present

    Cyber Security Consultant & Penetration Tester

    GCC Part-time

    Companies hire me to test their applications the way a real attacker would, with permission, and tell their developers exactly what's broken and how to fix it.

    • Penetration testing: authorized, hands-on attacks against client web and mobile applications to find weaknesses.
    • Reporting: each finding is written up with how to reproduce it, its business impact, and the fix.

  3. 2023 — Present

    Cyber Security Researcher

    HackerOne Part-time

    HackerOne is a platform where companies invite independent researchers to find security flaws in their products before criminals do. I test their live applications within published rules and report what I find.

    • Bug bounty: finding real vulnerabilities in production web applications across public and private programs.
    • Coordinated disclosure: working with vendors until issues are fixed. One of these reports became CVE-2024-36436, a publicly tracked vulnerability.

  4. Jun 2025 — Aug 2025

    Application Security Engineer

    Robusta Technology Group (RTG) Full-time

    The security engineer inside the product teams: helping developers ship features without security holes, rather than auditing them after the fact.

    • Vulnerability assessment: reviewing applications and features for security issues before and after release.
    • DevSecOps & secure development: automated security checks in the delivery pipeline and practical guidance for developers.

  5. Oct 2023 — Jan 2024

    Offensive Security Engineer

    Cybrany Part-time

    "Offensive" security means thinking like the attacker: simulating attacks on systems to find weaknesses first, and researching new kinds of vulnerabilities.

Brands from client engagements

A security engineer with a developer's background

I came to security from software development, and it still shapes how I work: I read code, not just responses. An exploit only makes sense once you understand what the developer intended, and a fix only sticks when it fits how the team actually builds.

That's why I work on both sides, shipping software and attacking it. Findings arrive with the context engineers need to fix them, and security becomes part of the delivery process instead of an afterthought.

Languages: Arabic · English

What I do

  1. Web & Mobile Penetration Testing

    Scoped assessments of web applications, APIs, and Android apps. Every finding is manually verified and documented with clear reproduction steps and remediation guidance.

    Web · Mobile · API · Red Teaming · Reporting

  2. Product Security & DevSecOps

    Security built into how software ships: automated checks in CI/CD, secure defaults, and release processes where speed and security stop competing.

    CI/CD · DevOps · Linux (Red Hat) · Secure Delivery

  3. Application Security

    Security embedded in product teams: secure code review, threat-informed testing across the SDLC, and working with developers rather than around them.

    Secure Code Review · Secure SDLC · JavaScript / Node.js · MongoDB

  4. Security Research & Bug Bounty

    Finding vulnerabilities in live systems and taking them through coordinated disclosure with the vendor until they are fixed.

    Bug Bounty · Recon · Vulnerability Research · Disclosure

  5. AI Security

    Assessing AI-powered features the way attackers approach them: prompt injection, weak authentication around model endpoints, and data exposure across a new attack surface.

    LLM Applications · Authentication · Abuse Cases
